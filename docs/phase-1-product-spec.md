# SAA Learn 阶段 1 产品定义

## 目标

验证最小学习闭环：输入一道题 → 获得结构化解析 → 用户确认 → 保存 → 通过搜索再次找到并查看原题与知识点。

## 分类策略

用户不需要预先提供完整分类。系统采用三层结构：

1. 稳定维度：AWS 服务、考试设计领域、题目形式、学习状态。
2. AI 候选标签：每次解析自动提取服务、场景、架构目标和关键词，保存前标记为“候选”。
3. 渐进治理：相似候选标签通过别名和人工合并归一化；未确认标签不会成为新的顶层分类。

首批稳定维度只保留：服务、题型、关键词。阶段 2 再根据真实题目积累决定是否增加层级。

## 页面与状态

| 页面 | 核心内容 | 主要操作 |
| --- | --- | --- |
| 题目输入 | 原始题目、选项 | 填入示例、开始解析 |
| 解析预览 | 原题、答案、逐项解析、知识点、候选标签 | 暂不保存、确认保存 |
| 我的题库 | 搜索、结果列表 | 添加题目、打开详情 |
| 题目详情 | 已保存的原题和完整解析 | 删除、解析新题 |
| Prompt 设置 | 系统 Prompt 编辑器 | 恢复默认、保存 |

## AI 输出契约

```json
{
  "answer": "B",
  "summary": "string",
  "services": ["Amazon S3"],
  "topics": ["成本优化"],
  "keywords": ["私有子网"],
  "optionNotes": [
    { "label": "A", "correct": false, "text": "string" }
  ],
  "knowledge": [
    { "title": "Gateway VPC Endpoint", "body": "string", "cue": "string" }
  ]
}
```

正式接入模型时，服务端必须校验 Schema、选项引用、单选/多选答案数量，并保留模型和 Prompt 版本。

## 原型的数据边界

- 阶段 1 使用浏览器本地存储；阶段 2 启动时会自动迁移到本地 D1 / SQLite。
- 当前只有内置示例题返回完整模拟解析；其他题目明确标记为待模型确认。
- 不把 AI 候选标签直接升级为正式分类。
- 下一阶段将本地数据迁移到数据库，并接入真实结构化模型输出。
